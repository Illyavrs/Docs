title: 角色與權限
description: 角色、權限與管理操作如何運作。
---

一個帳號可以持有多個角色，權限取聯集。`*` 代表全部權限；其餘權限都以精確名稱比對，沒有階層或前綴繼承。公開註冊會取得 `player` 角色，請不要把 `*` 給這個角色。

管理面板會顯示帳號有權限的區域（例如只持有 `chat.moderate` 就能開啟聊天區），而 API 每次呼叫都會檢查權限。`admin.view` 只允許讀取管理用的圖譜中繼資料，不隱含任何寫入權限。

## 權限

| 權限                                 | 允許                                                   |
| ------------------------------------ | ------------------------------------------------------ |
| `roles.manage`                       | 在自己的權限範圍內建立、編輯、指派與移除角色           |
| `users.moderate`                     | 查看帳號 email；限制或解除限制其他帳號                 |
| `users.sessions.revoke`              | 撤銷自己可管理帳號的網站、stable、lazer 登入           |
| `chat.moderate`                      | 查詢玩家、設定或解除限時聊天禁言                       |
| `beatmaps.moderate`                  | 變更圖譜難度狀態                                       |
| `beatmaps.rank.request`              | 提交排名申請                                           |
| `beatmaps.rank.review`               | 查看申請佇列並拒絕申請（核准另須 `beatmaps.moderate`） |
| `beatmaps.upload`、`beatmaps.import` | 上傳伺服器圖譜；從官方匯入                             |
| `scores.moderate`                    | 審核成績；逐筆或在管理中心「重算成績」分頁批次重算 pp  |
| `announcements.manage`               | 撰寫草稿、編輯、發布與封存公告                         |
| `rewards.manage`                     | 建立、編輯、上架、下架與移除尚未被購買的獎勵商品       |
| `audit.read`                         | 查看管理操作紀錄                                       |
| `chat.send`、`social.manage`         | 發送聊天；管理自己的好友與封鎖                         |

## 內建角色與規則

- `player`、`moderator`、`administrator` 不能刪除。`administrator` 必須保留 `*`。自訂角色須先從所有帳號解除指派才能刪除。
- 必須永遠保留至少一個未受限制且持有 `*` 的帳號。
- 權限有限的角色管理者只能新增或移除自己持有的權限，不能降低較高權限帳號，也不能撤銷其登入。
- 限制帳號需要 `users.moderate`；限制持有 `*` 的帳號另須 `*`，且沒有人可以限制自己。
- `beatmap_nominator` 只有聊天、上傳、匯入、審核、申請與審閱權限。角色名稱不代表任何權限。

## 角色徽章

角色可以像 osu-web 的群組一樣，在個人檔案顯示成有顏色的徽章。在角色表單勾選「在玩家個人檔案顯示此角色徽章」，填入最多 8 個字元的短標籤（例如 `MOD`、`DEV`）並選擇顏色即可。徽章會顯示在網站與 lazer 個人檔案的玩家名稱下方，滑鼠移上去會顯示完整角色名稱。沒有勾選徽章的角色（例如 `player`）不會公開顯示。內建的 `moderator` 與 `administrator` 預設有 `MOD`、`ADMIN` 徽章，標籤與顏色可以修改，但管理員的名稱與權限不能改。

## 圖譜狀態與排名申請

狀態屬於每一個難度：Graveyard、WIP、Pending、Unranked、Ranked 或 Loved。新上傳的圖譜從 Graveyard 開始。讓某個難度 Ranked 不會影響同組的其他難度。

玩家可以為自己上傳且未排名的圖譜，以及官方 Pending 或 Graveyard 的圖譜提出排名申請。一個圖譜組同時只能有一筆待審申請；每位玩家最多有 5 筆未結案，24 小時內最多送出 10 筆。理由為 1 至 1000 字。核准時要選擇特定難度，並帶入申請與各難度的預期版本；版本過期會回傳 409，不會覆蓋。

## 其他管理操作

- **成績**：審核須帶入預期的 `moderation_revision`；過期時回傳 409 `score_moderation_conflict`。
- **成績重算**：管理中心的「重算成績」分頁會重新計算已儲存成績的 pp。可依玩家（名稱或 ID）、一般或 Relax、模式、日期範圍、譜面 ID、審核狀態、目前 pp 範圍或指定成績 ID 篩選，也可以只重算用舊算法計算的成績。開始前會先預覽符合的數量、依類型與模式的分布和最新的幾筆成績，確認後才會變動。工作在背景一次執行一個，可以隨時取消；已處理的成績保留新的 pp。每個工作會列出 pp 變化最大的成績，以及所有被略過或失敗的成績。失敗與已拒絕的成績、被限制的玩家不會被重算。每筆成績都會記錄使用的計算方式，「舊算法」就是靠這個判斷。開始、取消與結束工作都會寫入稽核紀錄；操作者失去 `scores.moderate` 時，工作會自動停止。
- **聊天禁言**：未來時間（最長 30 天）與 1 至 500 字的理由（僅私密稽核）。只阻止新訊息；玩家仍可登入、遊玩與閱讀。
- **登入撤銷**：不會限制帳號。長連線會在下一次驗證檢查時發現。
- **公告**：編輯須帶入目前的 `revision`；不符時回傳 409 `announcement_conflict`。草稿與已封存的內容絕不公開提供。
- **獎勵**：`rewards.manage` 可開啟獎勵商品管理工具。管理者可以建立與編輯稱號、頭像框，將商品上架或下架；只有從未被購買的商品才能刪除。如果刪除時回傳 `reward_in_use`，請改為下架。已被購買的商品下架後會停止新購買，但持有者仍可裝備。價格為 1 至 100,000 星塵，稱號文字為 1 至 32 字元，說明為純文字。頭像框使用內建的單線、雙線或四角邊框樣式。商店初始為空，由管理者選擇要發布的商品。此權限不提供其他玩家私人錢包或庫存的讀取權限。

每一次管理寫入都會在交易內重新讀取操作者的登入、限制與權限，並與稽核紀錄一起提交。
